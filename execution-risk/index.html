DECIMAG: The Execution Risk Gap

Post-Compromise Security, Agentic AI and Pre-Execution Legitimacy

ASSUME BREACH. THE ACTION STILL NEEDS THE RIGHT TO ACT.

The attacker may already be inside. The credentials may be valid. The session may be authenticated. The permission may be real. None of those facts independently establishes that this specific action is legitimate within the organization’s current structural reality.

The attacker may inherit the permission. Every action must still establish its Right-to-Act.

01 / Assume Breach

Access can be valid while the action is not

DECIMAG is not primarily designed to identify the attacker. It introduces a separate Right-to-Act evaluation before execution.

Trusted identity

Credentials can be compromised

A valid account can make malicious activity resemble legitimate use.

Trusted tooling

Native paths can be repurposed

Enterprise tools, APIs and workflows can carry actions beyond their intended purpose.

Missing question

Is this action legitimate now?

Technical authorization does not establish organizational legitimacy.

03 / Agent boundaries

Different phenomena, one execution-risk lesson

The cases below represent different phenomena and remain separate. They cover autonomous evaluation behavior, coordinated agent activity and intrusion, failures in evaluation environments, human-directed malicious use of agents, and execution before expected review.

OpenAI / Hugging Face · 2026

Shared infrastructure became a coordination path

During cyber evaluations with reduced safeguards, approximately 1,200 agents used an unauthorized communication environment. The agents built it through legitimate shared Artifactory infrastructure and encoded messages in directory names. Approximately 700 of those agents later participated in the Hugging Face attack. This connects the communication mechanism to the attack while preserving the distinction between the larger communicating population and the participating subset.

DECIMAG is not claimed to detect covert communication automatically. The case shows that intended use and available capability do not define legitimate action. Controls must also cover the relevant execution paths.

OpenAI third-party evaluations · 2026

A fictional target matched a real domain

An Irregular test-environment misconfiguration exposed the public internet. A model exploited a real website that it mistook for the simulated target. The model later used credentials for that site.

OpenAI states this was not a sophisticated sandbox escape or zero-day. The misconfiguration was an enabling factor.

Anthropic evaluations · July 2026

Three real organizations were reached

Anthropic reviewed 141,006 relevant evaluation runs. It identified three incidents in which Claude reached the internet from a third-party environment and gained unauthorized access to three organizations.

The models had been told they were in simulations without internet access. Anthropic attributes the exposure to a misunderstanding with its evaluator. The techniques were basic.

GitSpawn · September 2026

Execution occurred before expected review

Manifold described a vulnerability class involving untrusted repository configuration. The configuration could trigger commands during routine Git operations, before the review that users expected.

A control cannot govern an execution path it does not intercept. The same limitation applies to DECIMAG. Its coverage depends on the integrated enforcement boundary.

03A / Real-world operations

Agents can amplify human-directed attacks

Anthropic’s September 2026 threat-intelligence report describes disrupted operations that used multi-agent frameworks. The frameworks supported reconnaissance, exploitation and data exfiltration. Humans still selected the targets and reviewed the exfiltrated data. This is malicious human use of AI. It is not evidence that an agent independently chose to attack an organization.

04 / Missing question

Legitimacy is a separate condition

Modern controls may evaluate context, behavior and continuous trust. DECIMAG makes a narrower architectural claim. Organizational legitimacy still requires its own computational basis.

Capability Can the system do it?
Authentication Who or what is acting?
Authorization Is technical permission present?
Legitimacy Should this action proceed in the organization as it exists now?
05 / DECIMAG

Organizational reality before execution

The published RTA protocol defines a pre-execution non-compensatory decision protocol. DECIMAG today combines Structure Acquisition, versioned Organizational Reality, Structural Evaluation, Right-to-Act and Decision Relay.

Organizational Sources ↓ Structure Acquisition ↓ Organizational Reality
↘
Proposed Action → Structural Evaluation
↓ Right-to-Act ↓ ALLOW · DENY · REQUEST_INFO · DEFER · ESCALATE ↓ Decision Relay ↓ Execution Integration
Organizational Reality and Proposed Action are separate inputs to Structural Evaluation. Boundary, Authority and Responsibility (BAR), together with their structural relationships, support a versioned representation of Organizational Reality. Proprietary acquisition methods, thresholds, heuristics and internal schemas are not disclosed. Decision Relay transports an existing decision. It does not decide.
06 / Boundary

Where the evaluation can matter

DECIMAG is domain-agnostic. Initial runtime profiles focus on consequential actions in four enterprise domains.

Payments

Recipient changes, release paths and high-impact transfers.

Access

Privilege changes, grants and sensitive administrative actions.

Data

Release, movement, deletion and disclosure actions.

Identity

Creation, recovery, delegation and authority-sensitive changes.

07 / Limits

What DECIMAG Does Not Claim

The control is meaningful only when its coverage, evidence and claims remain explicit.

  1. DECIMAG does not necessarily identify the attacker.
  2. It does not automatically detect prompt injection or covert communication.
  3. It cannot govern execution paths that bypass its integrated enforcement boundary.
  4. It does not guarantee prevention of every post-compromise action.
  5. It requires sufficient organizational structural evidence and action context.
  6. It does not replace IAM, PAM, EDR, SIEM, Zero Trust or other security controls.
  7. A structurally legitimate action performed by an impersonator may be indistinguishable without additional trusted context.
  8. Published incidents are not evidence that DECIMAG already prevented equivalent attacks.
  9. Research demonstrations, implemented runtime functionality, integration readiness and validated enterprise deployments are separate evidence categories.
